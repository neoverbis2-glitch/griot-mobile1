A sensação finalGRIOT Quick Chat

O Quick Chat é a camada de conversa rápida do GRIOT.

Ele existe para resolver um problema simples: nem tudo merece virar projeto, tarefa, agente ou execução persistente.

Às vezes o utilizador só quer perguntar alguma coisa, testar uma ideia, esclarecer uma dúvida, pedir uma explicação ou conversar diretamente com um modelo específico sem criar estrutura desnecessária dentro do workspace.

O Quick Chat serve exatamente para isso.

Ao abrir o Quick Chat, o utilizador escolhe diretamente o modelo que quer usar, como GPT, Gemini, Claude, Grok ou qualquer outro modelo disponível na sua conta.

A partir daí, entra numa conversa leve e imediata.

Sem projeto obrigatório.

Sem agente.

Sem pipeline.

Sem criar tarefas.

Sem poluir o histórico principal do GRIOT.

O objetivo é reduzir a distância entre a dúvida e a resposta.

O utilizador pode simplesmente abrir, escolher o modelo e perguntar.

Por exemplo:

“Explica-me este erro.”

“Resume isto.”

“O que achas desta arquitetura?”

“Traduz este texto.”

“Ajuda-me a pensar nesta ideia.”

“Qual destas duas abordagens é melhor?”

Tudo isso pode acontecer sem transformar uma pergunta de 30 segundos num projeto permanente.

Relação com o GRIOT

Apesar de ser mais simples, o Quick Chat continua completamente integrado com a conta do GRIOT.

Ele utiliza o mesmo sistema de autenticação, modelos, utilização, limites, histórico e infraestrutura do ecossistema.

A diferença está na intenção.

No Workspace, o utilizador está a trabalhar em algo.

No Quick Chat, o utilizador está simplesmente a conversar.

Essa separação mantém o GRIOT organizado sem remover a liberdade de usar uma IA de forma espontânea.

Escolha direta do modelo

Uma característica importante do Quick Chat é a possibilidade de escolher diretamente o modelo.

O utilizador pode tocar no seletor e trocar entre os modelos disponíveis.

Por exemplo:

GPT-5.6 SOL

Gemini

Claude

Grok

ou qualquer outro modelo integrado no futuro.

O GRIOT não tenta esconder necessariamente qual IA está a responder.

No Quick Chat, essa escolha pode fazer parte da experiência.

Isso também permite que utilizadores mais avançados escolham o modelo mais adequado para cada situação.

Um modelo para raciocínio.

Outro para código.

Outro para escrita.

Outro para velocidade.

Conversas temporárias ou guardadas

Por padrão, uma conversa de Quick Chat pode ser tratada como leve e descartável.

Mas o utilizador pode escolher guardá-la.

Se uma conversa começar pequena e evoluir para algo importante, existe uma ação simples:

Transformar em Projeto

Nesse momento, o GRIOT pode criar um novo Workspace e transferir para ele a conversa, anexos e contexto relevante.

Assim, uma simples pergunta pode crescer naturalmente sem obrigar o utilizador a decidir isso antecipadamente.

Quick Chat com contexto de projeto

O Quick Chat também pode receber contexto sem se tornar parte do projeto.

Por exemplo, dentro de um projeto o utilizador pode tocar em:

Perguntar no Quick Chat

O GRIOT envia apenas o contexto selecionado — um ficheiro, uma imagem, um erro, uma decisão ou um pequeno trecho do projeto — para a conversa rápida.

A resposta não altera automaticamente o projeto.

Isso é importante.

O Quick Chat pode observar e aconselhar sem executar.

Se o utilizador gostar da resposta, pode depois mandar:

Aplicar ao Projeto

Dessa forma, consulta e execução continuam claramente separadas.

Filosofia

O Quick Chat não compete com o Workspace.

Ele protege o Workspace.

Mantém perguntas pequenas fora dos projetos e deixa o GRIOT principal reservado para trabalho estruturado, persistente e executável.

A diferença pode ser resumida assim:

Quick Chat: pensar, perguntar, explorar.

Workspace: construir, executar, acompanhar.

O utilizador não precisa decidir antecipadamente se algo será importante.

Ele começa no Quick Chat.

Se crescer, transforma-se em projeto.

Essa é precisamente a função do Quick Chat dentro do GRIOT: oferecer liberdade sem sacrificar organização.

## Runtime de execução real

O runtime do GRIOT Mobile não fabrica resultados de shell, Git ou testes. As ações são autenticadas no servidor e encaminhadas para `runtime-runner`, onde são executadas dentro do workspace atribuído.

Variáveis necessárias no servidor:

```text
GRIOT_RUNTIME_EXECUTOR_URL=https://<runtime-host>
GRIOT_RUNTIME_SHARED_SECRET=<segredo-compartilhado>
```

A mesma `GRIOT_RUNTIME_SHARED_SECRET` deve existir no serviço `runtime-runner`. Nunca coloque esse segredo em `VITE_*`, no APK, nem em código cliente.

O `runtime-runner` é deliberadamente mínimo e sem dependências de aplicação. O container instala `git`, `bash` e certificados, expõe apenas `POST /v1/actions/execute` e exige assinatura HMAC com timestamp.

### GitHub Actions

O Android é construído no GitHub Actions. Não é necessário Android Studio: o workflow prepara Node 22, Java 21, Android SDK, compila o bundle web, sincroniza o Capacitor e gera o APK como artifact.

O workflow do runtime também valida a sintaxe do runner e constrói a imagem Docker.

> Nota: o `runtime-runner` precisa receber um workspace real e, para operações `git.push`, credenciais do repositório devem ser configuradas no ambiente de execução. O GRIOT não guarda essas credenciais no cliente.
